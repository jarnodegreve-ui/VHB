# PlanX — VHB-personeelsportaal

Portaal voor het busbedrijf (GitHub-repo `jarnodegreve-ui/VHB`). Vite + React + TS + Tailwind (`src/`), serverless API (`api/`), Supabase. Prod = Vercel-project `vhb` → vhb-five.vercel.app (Pro). **`vhb-planner` is een ánder Vercel-project** (rostering) — nooit daarheen deployen.

## Git & sessies
- **Nooit `git add -A`** — parallelle sessies delen deze working tree (rostering/, losse WIP). Stage expliciete paden; voor gedeelde bestanden (api/index.ts, vercel.json): aparte git-worktree vanaf origin/main.
- Features landen via feature-branch + PR, niet rechtstreeks op main.
- `rostering/` = geneste eigen repo (CP-SAT-solver, eigen memory) — niet aanraken tenzij gevraagd.

## API & deploy
- **Elk bestand in `api/` wordt een aparte Vercel-functie.** Gedeelde modules → `api/_lib/` (underscore bouwt niet als functie). vercel.json rewrites sturen alles naar api/index.ts.
- Deploy verifiëren via Vercel-MCP (`list_deployments`, `get_deployment_build_logs`) — niet met curl-salvo's (bot-challenge) of de GitHub-deployments-API. Functionele marker: nieuw endpoint 401 = live, 404 = oud. Bundel-hash lokaal vs. live vergelijken werkt NIET.
- Crons in vercel.json, CRON_SECRET-beveiligd (Pro: frequenter dan dagelijks mag).
- **Gedeelde API-contracten (zod)** staan in `shared/schemas/` (repo-root, naast `api/` en `src/` — géén cross-import api↔src). Eén schema per record (user, diversion, update) valideert het formulier én de request-body; de NL-foutteksten per veld staan dáár. `api/` importeert `../shared/schemas/x.js`, `src/` `../../shared/schemas/x`; Vercel traceert imports buiten `api/` gewoon mee en `shared/` wordt geen functie (staat niet onder `api/`); tsconfig en vitest nemen `shared/` mee. Server bij fouten: 400 `{ error: 'Ongeldige invoer', details, veldfouten: { veld: tekst } }` (`api/_lib/valideer.ts`); client: `src/lib/valideer.ts` (`valideer` + `veldfoutenUitAntwoord`) → Field error-prop, en `perRecord(…, opVeldfouten)` brengt server-veldfouten naar het formulier.

## Database
- Supabase met **quoted camelCase-identifiers** (anders dan snake_case elders). Migraties handmatig in SQL Editor, idempotent; hergebruik `public.set_updated_at()` en `current_app_user_role()` uit setup_security.sql. Kolomnamen moeten matchen met api/storage.ts + api/types.ts. Elke .sql eerst langs de `supabase-sql-reviewer` (hook doet dit automatisch).

Géén `dark:`-utilities en géén `.dark`-overrides op utility-klassen meer schrijven — het flipt vanzelf.

## Design-systeem & schil (sinds next-level, 09-2026)
- **Primitieven eerst**: Button/IconButton/FilterChip/Switch (primitives.tsx), Card/CardHeader (Card.tsx, tones muted/dashed/accent/warning/danger/success/info), Field/Input/Textarea/Select (Field.tsx — fouten bij het veld, nooit als toast), Chip/Badge, Table.tsx (TableToolbar, useSort/SortTh, Checkbox, BulkBar, StickyThead, Paginering; `TableShell sticky`), InfoTip (uitleg = popover, geen alinea's in kaarten). Geen rauwe `<button>` zonder `{/* rauw: reden */}`. `npm run lint:design` bewaakt dit (ook in CI).
- **Typografie-rollen**: `text-page-title` (h1, één per scherm via PageHeader), `text-section-title`, `text-card-title`, `text-label`, `text-micro`. Motion via `DUR`/`EASE` (src/lib/motion.ts); iconen 12/14/16/18/20/24.
- **Routing**: de URL is de bron (src/app/router.ts; `useRouteParam` voor maand-segmenten, `useQueryParam` voor ?zoek=); elk scherm staat één keer in `src/app/routes.tsx` (pad, label, icoon, sectie, rollen) — sidebar, bottom-nav, ⌘K-palette (met acties en recent), rol-guard en topbar-titel volgen daaruit. Nieuw scherm = één regel in ROUTES + `View`-type + loader in `src/app/viewLoaders.ts` (lazy + prefetch) + een case in App.tsx. Overlays gebruiken `useHistoryDismiss` (terugknop sluit ze). App.tsx = auth/sessie/thema/toasts/schil.
- **Datalaag**: `src/app/data/*.ts` per domein (planning, verlof, ruil, mensen, communicatie, activiteit) met gedeelde vangrails in `kern.ts`; `useAppData` componeert ze; views lezen bij voorkeur via `useAppDataContext()` (AppDataContext.tsx) i.p.v. props. **Per-record API** voor gebruikers, omleidingen en updates (PUT/:id, POST /one, DELETE/:id met `_rev` + `X-Record-Revision`, 409 met actueel record); bijwerkingen in `api/_lib/recordWrites.ts`, ook gebruikt door de collectie-routes. Bulk/import blijft collectie-POST.
- **Mijn dag** (`/mijn-dag`) is het broekzakscherm van de chauffeur (tijdlijn, nu-lijn, ritblad, omleidingen); bottom-nav chauffeur = Dashboard · Mijn dag · Rooster · Omleidingen · Verlof (Ritbladen via Meer).
- **Datums**: nooit `<input type="date">` (design-lint verbiedt het) — `DateInput` in een `Field` (src/components/DatePicker.tsx; popover op desktop, sheet op mobiel, ISO-waarde zoals native). **Personen** in lijsten krijgen `<Avatar naam>` (initialen, vaste gedempte tint per naam); de topbar-avatar blijft goud. **Lege staten** via `EmptyState variant="leeg|klaar|fout"` (lus-motief, BrandMotief.tsx) — 'klaar' als leeg = alles afgehandeld. **Verwijderen** van één item: geen bevestigingsmodal maar meteen doen + undo-toast (`metOngedaan` in src/lib/ongedaan.ts; toast-optie `ongedaan`); bulk houdt de modal. **Wat is nieuw**: na een release één item toevoegen in src/app/watIsNieuw.ts (nieuwste bovenaan, regels per rol). **/beheer/designsysteem** (admin) toont alle primitieven en tokens — nieuwe primitief = ook daar een voorbeeld; het scherm zit in de visuele regressie.
- **Dienst als instrument**: `DienstBalk` (src/components/DienstBalk.tsx, geometrie in src/lib/dienstBalk.ts) is dé weergave van een dag — Mijn dag (volledig, met uurstreepjes) en de Vandaag-tegel (`compact`); geen losse voortgangsbalken meer per blok. Ritblad: `RitbladViewer` zoekt client-side (pdfjs, lazy) de pagina's van het dienstnummer in de bundel; `openHuidigRitblad()` = fallback hele bundel; pdf-chunks tellen niet mee in check-bundle-size.
- **iOS-statusbalk**: `black-translucent` + `.statusbalk-strook` (env(safe-area-inset-top)) bovenaan topbar, skeleton en SlideOver; nieuwe schermvullende lagen aan de bovenkant krijgen dezelfde inset (Modal en palette doen dat al). Nooit terug naar `black`: dan schuift de webview na een herlaad soms achter de statusbalk.
- **Desktop ≠ gestapeld mobiel**: lijst+detail (master-detail) op `lg+` via `useMinWidth` (src/lib); mobiel blijft de kaartlijst. Visuele regressie: `VISUEEL_DESKTOP=1 VISUEEL_ALLE_THEMAS=1 AUDIT_OUT=… node scripts/mobile-audit.mjs` + `scripts/screenshot-diff.py`.
